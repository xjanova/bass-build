## งานที่เหลือ (เรียงตามลำดับที่ควรทำ)

### 0. ตรวจงานขั้วต่อและมือจับ (ค้างจากรอบก่อน)
คอมมิท `2d7095b` สร้างเสร็จและทดสอบผ่าน แต่ยังไม่ผ่านขั้นตรวจ ให้ผู้ตรวจ 2 มุมดูก่อนทำงานอื่น แล้วแก้ตามที่พบ
- มุมความถูกต้อง: ตำแหน่งเทียบกับท่อหลัง BP6 ท่อพับ และทรงลิ่ม, ปริมาตรที่กินเข้าไปในตู้, ปัญหาสร้างไม่ได้ (`terminal`, `handles`), `geoKey` ใน `App.tsx`
- มุมผลิตภัณฑ์: ข้อความไทย และการติดป้ายค่าประมาณ

### 1. รอยต่อ: ชนตรง / บังใบ / เข้ามุม 45° (เฟส 2 และ 3)
- ฟิลด์ `joint: 'butt' | 'rabbet' | 'miter'` (ใส่ใน `ENUMS` ที่ `data/compare.ts`)
- ขนาดภายในและภายนอกเท่าเดิม เปลี่ยนแค่ขนาดตัดของแต่ละแผ่นใน `partsFor`
  - บังใบ: แผ่นที่ชนเข้าหน้าแผ่นอื่นยาวขึ้น t/2 และบอกร่องบังใบในหมายเหตุ
  - เข้ามุม: แผ่นนอกเต็มขนาดภายนอก ขอบตัดเอียง 45°
- ทรงลิ่มแบบเข้ามุม: มุมไม่ใช่ 45° ทำให้ถูกหรือปิดตัวเลือกพร้อมบอกเหตุผล
- รายการตัด CSV/DXF/SVG และขั้นตอนประกอบต้องตามรอยต่อที่เลือก พื้นที่แผ่นและน้ำหนักต้องตาม

### 2. หน่วย มม./ซม./นิ้ว และ ลิตร/ฟุต³
- เก็บเป็นค่าตั้งของผู้ใช้ ไม่ใช่ใน `Design` (ไม่ให้เข้า undo) และจำไว้ใน localStorage
- ทำตัวช่วย format กลางตัวเดียว ใช้กับทุกตัวเลขบนจอ: แผงขวา, `ShapeSection`, ชิปขนาด, ป้ายขนาดในฉาก 3D (`Engine.buildDims`), ป้ายระยะตอนลากลำโพง, โครงสร้างงานด้านซ้าย, พิมพ์เขียว
- ช่องกรอก (`NumField` ของขนาด) ต้องรับค่าในหน่วยที่เลือก
- ภายในยังเก็บเป็นเมตรหรือมิลลิเมตรเหมือนเดิม

### 3. บันทึกเวอร์ชันและไฟล์ `.bassbuild`
- ปุ่มบันทึกเวอร์ชัน (Rev A, B, C…) ใช้ป้าย "Rev A" ที่แถบบนเป็นชื่อเวอร์ชันปัจจุบัน มีรายการเวอร์ชันให้เปิดกลับ เปลี่ยนชื่อ และลบ (ลบต้องยืนยัน)
- เก็บใน localStorage ถ้าเชื่อมเซิร์ฟเวอร์ C# ได้ให้ใช้ `/api/projects` (ดู `server/BassBuild.Server/ProjectEndpoints.cs`)
- ส่งออกและนำเข้าไฟล์ `.bassbuild` (JSON):
  - เก็บ design, ข้อมูลลำโพงเต็มชุด (ลำโพงที่ผู้ใช้เพิ่มเองจะได้เปิดที่เครื่องอื่นได้) และเลขเวอร์ชันแอป
  - ตอนนำเข้าตรวจด้วย `sanitizeDesign` และจำกัดขนาดไฟล์

### 4. ตู้ทรงกระบอก
- `shape: 'cylinder'` สำหรับตู้ปิดและตู้เปิด ตั้งตรง แผงหน้าเป็นฝากลมปลายท่อ
- ท่อหน้าต้องเป็นท่อกลม (ท่อสลอตทำไม่ได้)
- `sizeBox` คิดรัศมีและความยาว และตรวจแม่เหล็ก ท่อ และจำนวนลำโพงบนฝากลม
- ในโมเดล 3D และพิมพ์เขียว:
  - ฝากลม 2 แผ่นตัดจากแผ่นไม้
  - ตัวท่อเป็นของซื้อ (ท่อกระดาษหรือ PVC ใหญ่) อยู่ในรายการวัสดุพร้อมขนาดในและความยาว

### 5. ตรวจทั้งเฟส แล้วปิดเฟส 2
- เทียบกับ `docs/PLAN.md` หัวข้อ 2C และตารางเฟส 2
- อัปเดตบรรทัดสถานะใน PLAN, คำอธิบาย PR, เลขเวอร์ชันเป็น 0.3.0 และไฟล์นี้

### ตัดออกจากเฟส 2 (บอกเหตุผลไว้ใน PLAN ตอนปิดเฟส)
- **ทรงกลม/พีระมิด/วาดโปรไฟล์อิสระ:** ทำจากแผ่นไม้ได้ยาก หรือต้องมีตัวแก้ไขรูปทรงเต็มรูปแบบ
- **ตัวแปลงรูปทรงอิสระเป็นวงจร:** ตอนนี้ตู้เป็นแบบพาราเมตริก ทุกชิ้นส่วนรู้ความหมายและเข้าวงจรได้ตรง ๆ ส่วนรูปทรงอิสระจริงต้องใช้ FDTD ยืนยันในเฟส 6
- **ยิงลง/push-pull/กลับหัว:** ฟิสิกส์เหมือนเดิม แต่การจัดวางต่างกันมาก
- **ท่อกลมแบบมีข้องอ**
- **โซนยัดใยเฉพาะผนัง**

## วิธีทำงานในโปรเจกต์นี้

- ตรวจก่อน commit ทุกครั้ง (จาก root): `npm run typecheck`, `npm test`, `VITE_STATIC=1 npm run build`
- อะไรที่ทำให้ตู้สร้างจริงไม่ได้ต้องเป็น `BuildProblem` (`sim/model.ts`) แถบเลื่อนจะหยุดตรงนั้นเอง (`sim/buildable.ts`)
- ฟิลด์ใหม่ใน `Design`: ใส่ค่าเริ่มต้นใน `DEFAULT_DESIGN` ถ้าเป็นตัวเลือกแบบข้อความให้ใส่ `ENUMS` ด้วย ถ้ามีผลกับรูปทรง 3D ให้ใส่ใน `geoKey` ของ `App.tsx`
- ข้อความบนจอเป็นภาษาไทย คอมเมนต์ในโค้ดเป็นอังกฤษ ค่าที่ไม่ได้มาจาก datasheet หรือ seed ต้องติดป้ายว่าประมาณ
- ทดสอบในเบราว์เซอร์:
  - เปิดเซิร์ฟเวอร์ด้วย `VITE_STATIC=1 npx vite --config apps/web/vite.config.ts apps/web --port 5173`
  - ใช้ Playwright ที่ติดตั้งไว้แล้ว เครื่องคลาวด์ไม่มีการ์ดจอ ภาพจึงช้ามาก ให้ตั้ง timeout 90 วินาที
  - ปิดเซิร์ฟเวอร์ด้วย `kill <pid>` ห้ามใช้ `pkill -f vite` เพราะจะฆ่า shell ตัวเองไปด้วย
- ถ้าใช้ agent หลายตัวพร้อมกัน ให้ทำทีละฟีเจอร์ตามลำดับ เพราะทุกฟีเจอร์แก้ไฟล์หลักชุดเดียวกัน (`model.ts`, `layout.ts`, `blueprint.ts`, `enclosure.ts`, `RightPanel.tsx`)
